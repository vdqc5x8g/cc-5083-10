# 景深融合 · 焦点融合图像恢复台

静态多焦点照片的**景深融合（focus stacking）**工具。它检查尺寸与配准关系，
逐像素估计清晰度，生成**平滑但保留遮挡边缘**的选择权重并重建像素；目标是
**扩大清晰覆盖范围**，不反演三维深度，也**不做多图平均**。所有输入在同一位置
都模糊时，结果如实标记为**不可靠**，不凭空补细节。

- 纯 JavaScript，零依赖。核心算法（`src/core/`）在浏览器与 Node 间共享同一份代码。
- 自带 PNG 8/16 位编解码（含灰度/RGB/RGBA/调色板、Adam7、tEXt），无需第三方库。
- 输出默认 **16 位** PNG，保留足够位深。
- 无预画掩码：清晰度、权重、可靠度都是逐像素实算出来的。

## 图形入口（主要入口）

焦点融合的图像恢复窗口是本工具的主界面。启动静态服务器后，在浏览器打开：

```bash
npm start                 # 等价于 node bin/serve.js
# 控制台会打印：
#   focus-fusion GUI (image-restoration window): http://127.0.0.1:8080/
```

打开 <http://127.0.0.1:8080/> 即进入**焦点融合图像恢复窗口**。界面分三栏：

- **左栏 · 焦点组**：载入示例（合成测试图 / 自制静物序列）或“添加图片…”；
  每张缩略图可勾选纳入求解、可点“编辑有效区”、可移除。底部可切换
  **相似配准**、**曝光匹配（仅清晰度）**、输出位深，并触发“重新计算融合”、
  “导出融合图”、“导出选择图”。
- **中栏 · 结果区（画布）**：四个视图——**融合结果 / 权重分布 / 可靠度 /
  分屏对照**，可叠加可靠度、显示有效区。结果区呈现的是真实融合像素与
  真实权重分布，不是占位图。
  - **权重分布**视图支持“主导焦点着色”和“单片权重热力”，配右栏图例。
  - **分屏对照**：左半为融合结果，右半为所选输入片。
  - **可靠度**视图：红=不可靠（不补细节）、黄=边缘/存疑、灰=无数据。
- **右栏 · 结果面板**：**异常提示**（全部输入皆模糊、重影风险、配准置信度不足、
  尺寸不一致）、**融合统计**（可靠/边缘存疑/不可靠/无数据比例、平均可靠度、
  选择边缘宽度、重影指数、覆盖）、**配准关系**（每片的 NCC、缩放、旋转、位移）、
  **权重分布**图例。

### 编辑有效区（ROI）并重算

在左栏某张图上点“编辑有效区”，在弹窗中**拖动矩形**即可限制该图的参与区域；
可添加多个矩形（并集），也可“清空有效区（全部有效）”。点“应用并重新计算”后，
框外像素对该片视为无效，融合只使用框内像素——这对应“用户可限制某张图的
有效区域并重新计算”。

### 载入自己的照片

点“添加图片…”或直接把 PNG 拖到页面任意位置。要求同一场景、**尺寸一致**
（不一致会立即提示，融合前必须一致）。顺序不重要，配准会自动对齐。

> 示例数据位于 `demo/`。若该目录为空，先执行 `npm run demo`（见下）生成。

## 命令行（仅辅助）

命令行只作批量/脚本用途，图形窗口才是主入口。

```bash
node bin/focus-fusion.js <输出目录> <切片1.png> <切片2.png> [...]
```

选项：

| 选项 | 含义 |
| --- | --- |
| `--roi k:x,y,w,h` | 限制第 k 片（按输入顺序，0 起）到归一化矩形；可重复 |
| `--roi k:none` | 清除第 k 片的有效区限制 |
| `--exclude k` | 从自动求解中移除第 k 片；可重复 |
| `--bit-depth 8\|16` | 输出位深，默认 16 |
| `--no-registration` | 关闭相似配准 |
| `--report-only` | 只写 `report.json`，不写图片 |
| `--quiet` | 关闭进度与摘要输出 |

输出：`fused.png`（默认 16 位）、`selection.png`（主导焦点着色）、
`reliability.png`（可靠度叠加）、`weight-k.png`（每片权重热力）、`report.json`
（输入、参考帧、跳过的片、配准参数、统计、边缘宽度、重影指数、覆盖、异常）。

## 生成示例数据

```bash
npm run demo                              # 默认 demo/，320×240，两套场景
node bin/make-demo.js out --scene still --size 640x480
```

- **合成测试图**（`chart-*.png`）：明确几何与深度的受控景深图层，
  含焦点呼吸、亚像素漂移与噪声，附带 `chart-sharp-reference.png`。
- **自制静物序列**（`still-*.png`）：桌布、木桌面、印刷卡片、书堆、陶瓷杯、
  柠檬、香草枝，各物体处于不同深度，经同一薄透镜弥散圆模型渲染，附带
  `still-sharp-reference.png` 与 `manifest.json`。

两套场景都走 `src/core/synth.js` 中的薄透镜 CoC 模型
（`blur半径 = clamp(aperture·|1/depth − 1/focus|·w·0.075, 0, 12)`），
因此每个像素都有可核对的真值深度。

## 算法与处理政策

流水线（`src/core/fuse.js`），全部为实算：

1. **尺寸检查**：不一致直接拒绝，并给出明确错误。
2. **相似配准**（平移 + 统一缩放 + 旋转，**不做单应变换**——单应会把焦点呼吸
   错当成透视形变而吸收掉）。分级求解：金字塔平移 → 全分辨率角度 → 尺度 →
   联合精修 → 四分之一像素抛光；梯度加权 NCC 打分。配准置信度不足会作为异常
   提示，且该片可在自动求解中被跳过。
3. **线性光**：所有清晰度测量与融合在线性光空间进行； sRGB↔线性用 65536 项 LUT。
   每片曝光增益只修正**清晰度测量**，不影响融合辐射值。
4. **清晰度**（`src/core/focus.js`）：LoG（高斯拉普拉斯）焦点能量 + 高斯窗，
   减去噪声底（第 5 百分位）。有效区边界用 push-pull 补洞扩展，避免把边界
   当作高反差结构而误判清晰。
5. **选择权重**：相对证据（best / weakest 片能量比），经**引导滤波**精修——
   引导图为临时融合亮度，使权重斜坡吸附到真实遮挡边缘；多图归一化，
   非法区为 0。
6. **高反差/合成守卫**：裁剪像素降权；融合后比较所选片的边缘能量与融合结果的
   边缘能量，若输入确有锐边却在结果中消失，则该像素标为不可靠，而不是编造细节。
7. **“全部输入皆模糊”**：某结构像素上没有任何片携带可确认的边缘能量时，标为
   不可靠（红），不补细节。
8. **前景遮挡 / 轻微呼吸**：权重在遮挡边缘处被引导滤波收紧（选择边缘半高宽
   目标约 4px），单应变换被排除，从而避免把不同焦平面的轮廓拼成重影；重影
   指数与选择边缘宽度都在结果面板/报告中呈现。

## 目录结构

```
src/core/    共享算法（png, image, filters, focus, register, fuse, synth, stilllife）
src/web/     图形入口：index.html / style.css / main.js / fusion-worker.js
bin/         serve.js（GUI 服务器）、focus-fusion.js（辅助 CLI）、make-demo.js
demo/        生成的示例景深序列
test/        node:test 测试（含合成与静物真值核对）
```

浏览器内所有融合计算在 Web Worker 中执行，与 CLI/测试共用 `src/core/`；
预览缩放后展示，导出时按所选位深重新跑完整分辨率流水线（导出的像素是实算结果，
不是放大后的预览）。Node 环境没有 `createImageBitmap`，故 `test/worker.test.js`
只覆盖 Worker 的消息契约与真实结果，像素级端到端由 CLI 测试与核心测试覆盖。

## 依赖与运行环境

- Node ≥ 18（PNG 编解码使用标准库 `CompressionStream`/`DecompressionStream`）。
- 浏览器需支持 Web Worker（module 型）与 `CompressionStream`（现代 Chrome/Edge/Firefox/Safari）。
- 无 npm 依赖，无构建步骤。
